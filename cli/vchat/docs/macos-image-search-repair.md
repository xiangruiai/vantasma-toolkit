# macOS 图片密钥与搜索兼容修复记录

本次修复来自一次 macOS 本地安装与使用排障，范围是图片恢复、搜索表结构兼容及错误诊断。
下文只记录可复现的方法和验证结论，不包含聊天内容、图片、密钥或账号标识。

## 症状与定位

- 输入 sudo 密码后长时间无输出：当时的本地运行脚本把过程输出重定向到了日志，界面没有进度，不能据此判断密码错误或程序卡死。
- 图片扫描曾报告成功，但完整图片解码失败：旧扫描器只检查很短的文件头，大量候选中出现了假阳性。
- 加强校验后，原生扫描返回退出码 `6`：表示本次扫描没有找到通过校验的候选，不等于用户没有打开图片。
- 部分搜索命令假定固定的内容表版本或分片编号，遇到其他版本时失效；标准 SQLite 也无法加载微信的 `MMFtsTokenizer`。
- 一个解密后的资源库存在索引与底表不一致；该问题与图片密钥、分词器兼容分别处理。

CLI 的退出码 `70` 是上层失败状态。现在会另行报告安全分类后的原生退出原因，避免把不同失败都提示为“打开图片后重试”。

## 最终图片恢复路径

新增 `vchat image-key --local`，从 macOS 当前账号的本地 `kvcomm` 缓存元数据推导候选，无需 sudo 或扫描进程内存。
实现依据 [weixin-cli 的公开附件提取说明](https://github.com/erbanku/weixin-cli#附件提取图片)，独立编写。

流程为：匹配缓存数字标识与账号目录后缀，派生 AES 与 XOR 候选，再对该账号的本地附件做完整解码验证。
只有 Pillow 的 `verify()` 和完整 `load()` 均通过，才原子更新配置。
缓存缺失、账号不匹配、图片损坏或配置同时发生变化时，均不报告成功。

```bash
# 将依赖装到运行 vchat 的同一 Python 环境
python3 -m pip install cryptography zstandard Pillow

# 从已安装的 vchat 恢复图片密钥
vchat image-key --local

# 可选：明确指定当前账号下已下载的图片样本
vchat image-key --local --sample /path/to/image.dat
```

该命令只恢复图片配置，不重新签名微信，也不重新解密数据库。

## 关键代码修复

- **密钥与路径**：32 字符十六进制正确解码为 16 字节 AES key，保留旧格式兼容；使用实际 `db_storage` 路径定位附件。
- **图片解码**：检查 AES、明文、XOR 分段边界及 PKCS7；无效候选不输出图片文件。
- **原生候选检查**：短文件头仅作预筛，再检查图片结构；假阳性不会提前结束扫描；尾标记推导一致时才采用 XOR 候选。
- **配置更新**：限制到选定账号，核验进程归属，保留无关配置字段及所有者；写入权限为 `0600`，错误信息不转发密钥。
- **独立重试与诊断**：新增 `image-key` 命令，区分超时、进程访问、样本与未找到候选等错误。
- **搜索兼容**：动态发现联系人、消息及收藏的普通内容表；关键词参数绑定，表名严格筛选，跨分片合并保留独立记录。
- **帮助文案**：不再把普通内容查询描述为完整拼音 FTS，也不承诺固定倍数提速。

## 验证

- 82 项回归测试通过，覆盖候选假阳性、分段边界、账号隔离、配置写入、错误分类、本地缓存派生及搜索版本适配；新原生候选不会继承旧密钥的完整验证状态。
- 本地缓存恢复后，3 张不同的真实 JPEG 均通过完整解码；验证没有展示、上传图片或输出密钥。
- `vchat doctor`、`vchat ls 20`、`contacts-fast`、`search --fast` 和 `fav-search` 本机检查退出码均为 `0`。
- 原生扫描器通过 `-Wall -Wextra -Werror` 编译检查。

在仓库根目录重跑回归测试：

```bash
cd cli/vchat
python3 -m unittest discover -s tests
```

## 仍然存在的边界

- 未移植微信原生 `MMFtsTokenizer`；搜索修复使用普通内容表，不保证原生拼音分词语义或 FTS 虚表完整性检查可用。
- 资源索引曾在备份后的**解密副本**上执行定向 `REINDEX`，对比表数据、rowid 和 schema 后通过完整性检查；该操作不在本 PR 中自动执行，也没有修改微信原始加密库。重新解密后的新副本需重新检查。
- `migrate/unspportmsg.db` 本轮未恢复，未发现它阻塞当前图片与基础查询的代码证据。
- 验证结果只覆盖所测试的本地 JPEG，不保证所有历史图片、未下载原图或 WXGF/HEVC 等格式可恢复。
- 内存扫描仍有进程、区域大小、候选对齐及图片结构支持范围限制；退出码 `6` 本身不能确认具体盲区，重复扫描也不保证成功。
