# Taskboard 浏览器式工作区设计

## 目标

让祥瑞始终看到全部项目，并在不同项目的看板、当前议题和相关 Codex 对话之间一键切换，不再依赖返回按钮找回项目或看板。

## 已验证的当前路径

- 点击议题卡片后，`App.tsx` 的 `openTaskDetail()` 写入议题路由，`TaskDetail` 会替换整个看板。
- 点击相关对话后，网页发送 `taskboard:open-thread`，注入脚本关闭 Taskboard，再打开原生 Codex 对话。
- 因此丢失上下文发生在两个位置：Taskboard 内部整页替换，以及进入原生对话时关闭 Taskboard。

## 直接方案

### Taskboard 内部

- 左侧直接复用“选择项目”页的数据，以紧凑列表展示全部项目，按“已有议题”和“其他项目”分组。
- 点击左侧任一项目，右侧立即切换到该项目的看板，当前项目在列表中高亮。
- 议题只在右侧看板中呈现，不放入左侧项目列表。
- 顶部提供“看板”“当前议题”“相关对话”三个工作标签。
- 从其他工作页点击“看板”返回看板；已经处于看板时再次点击，折叠或展开左侧项目导航。
- 点击议题只切换右侧内容，左侧导航和顶部标签保留。
- “相关对话”只聚合已经关联 Codex thread 的议题，不伪造聊天内容。

### Codex 原生界面

- 从议题打开原生对话时，注入脚本登记一个临时工作标签。
- 原生顶部持续显示“看板”和已打开的相关对话。
- 点击“看板”恢复 Taskboard，点击对话标签回到对应原生对话。
- 标签只保留在当前 Codex 会话内，不引入额外持久化规则。

## 交互原则

- 借鉴 Tab Out 的“全局可见、点击聚焦既有内容、避免重复打开”原则。
- 视觉继续使用 Codex 当前的深色、紧凑、原生控件语言，不复制 Tab Out 的纸张风格。
- 本轮只改变这条主路径，不扩展兼容逻辑和二级管理能力。
